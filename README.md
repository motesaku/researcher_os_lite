# researcher_os_lite

**研究者のための、AI agent駆動研究環境の最小単位。**

このリポジトリは、Claude Code / Cursor / Antigravity / Codex といった
AI agentを「単発の作図ツール」から「自分の研究文脈を理解した共同作業者」
に育てるための、最小限の出発点です。

フルセットの研究者OSではなく、**思想の最小完全版**として設計されています。
1時間で全体を読めて、5分で最初の体験ができます。

---

## 何が問題か

研究の現場でAI agentを使うとき、多くの人が同じ壁に当たります。

- 毎回「私は気象研究者で、○○のデータを扱っていて...」と説明し直す
- AIに渡したコードが、自分のスタイル・規約と微妙に合わない
- 解析・作図・執筆が別々のツールに分断されて、文脈が散逸する
- 数ヶ月前の自分のコードを再開するとき、思い出す作業に時間が消える

これらは「AIの賢さ」の問題ではなく、**研究文脈をAIが扱える形に
整えていない**ことから来ます。

---

## このリポジトリの提案

AI agentに、毎回ゼロから説明する代わりに、**少数のテキストファイル**
を読ませる運用に切り替えます。

| ファイル | 役割 | 比喩 |
|---|---|---|
| `AGENTS.md` / `CLAUDE.md` | AI agentへの基本ルール | オフィスの規則集 |
| `SKILL.md` | 何ができる/できないか | 作業者のスキルシート |
| `examples/hello_research/PROMPT.md` | 漠然な依頼の出発点 | 上司の口頭指示 |

たったこれだけで、AI agentは「毎回新人」から「文脈を持った同僚」に
変わります。

### 複数AI agent対応について

`AGENTS.md` と `CLAUDE.md` は **同じ内容のファイル** を2つ置いています。
これは、AI agentごとに自動認識するファイル名が異なるためです。

- Claude Code → `CLAUDE.md` を自動認識
- Codex / Cursor / Antigravity → `AGENTS.md` を自動認識

どちらか片方を編集したら、**必ずもう一方にも同じ変更を反映してください**。
将来 `AGENTS.md` への業界統一が進めば、1ファイル運用に移行できます。

## 5分で試す

最小サンプル `examples/hello_research/` を用意しました。

```bash
git clone https://github.com/<your-account>/researcher_os_lite.git
cd researcher_os_lite/examples/hello_research
```

あとは `HOW_TO_RUN.md` の手順に従ってください。
お手元のAI agent（Claude Code / Cursor / Antigravity / Codex のどれでもOK）で、
5分以内に最初の出力が出ます。

## 次にどう育てるか

**具体的な手順は [GROWING_YOUR_OS.md](GROWING_YOUR_OS.md) を参照してください。**
過去の解析コード・データを接続しながら、Day 1 から段階的に育てる道筋をステップバイステップで書いてあります。

このliteは出発点です。あなたの研究文脈に合わせて、以下の順で育てることを推奨します。

（以下、便宜上 `CLAUDE.md` と表記しますが、`AGENTS.md` も同じ内容なので両方に同じ変更を反映してください）

1. **第1週**：このliteをそのまま動かす（CLAUDE.mdとSKILL.mdは編集しない）
2. **第2週**：CLAUDE.mdに「自分の研究の固有名詞」を3行だけ追加する
3. **第1ヶ月**：自分のよく使うデータパスやライブラリの好みを SKILL.md に追記する
4. **第3ヶ月**：自分の論文の主張強度ルール、図の規約などを CLAUDE.md に蓄積する
5. **半年〜**：フルセットの researcher_os 設計（Dataset Registry, Provenance Logger,
   Logic Audit など）を必要に応じて取り込む

**重要**：いきなり全部書こうとしないでください。研究で困ったときに
「これCLAUDE.mdに足しておこう」と書き加えるのが、唯一持続する育て方です。

## 設計思想（簡単に）

このリポジトリの背景には、以下の3つの考えがあります。

**1. AI agentは賢いが、文脈がなければ毎回「新人」に戻る。**
文脈ファイルは、AI agentの研究室内メモリである。

**2. 「コードの正誤」ではなく「計画の正誤」を握る。**
AI agentに実装させる前に、Planを書かせて読む。
それが研究者として判断点を握る最軽量の方法。

**3. 完璧を目指さない。困ったときに少し足す。**
研究で本当に必要だと気づいた規約だけが、続く運用になる。
